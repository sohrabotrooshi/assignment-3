# AI Jukebox

A generative music jukebox: original songs composed on the fly, generative
cover art for every track, and AI-spoken DJ commentary between tracks.

**Stack:** pure-Python (numpy) synthesis engine · macOS `say` voices · SVG art ·
single-file HTML player. No API keys required to run; the DJ scripts and lyrics
can optionally be upgraded to an LLM endpoint with `--llm`.

## Security & asset policy

- **Credentials stay local.** Copy `jukebox/.env.example` → `jukebox/.env` and
  fill in real values; `.env` is gitignored. The app reads `JUKEBOX_LLM_URL` /
  `JUKEBOX_LLM_MODEL` / `JUKEBOX_LLM_KEY` from the environment or that file;
  DJ speech uses `JUKEBOX_TTS_URL` / `JUKEBOX_TTS_KEY` (falls back to
  `JUKEBOX_LLM_KEY`). No secrets appear in browser code (the player is fully client-side and never
  sees a key), in logs, in this README, or in any committed file. Commits are
  scanned for key material before push.
- **Voice references are never stored or committed.** A custom DJ voice is
  read from a local path you pass (`--voice-ref` or `JUKEBOX_DJ_VOICE_REF`),
  validated (.mp3/.wav, real audio, ≤ 10 MB), and sent to Chatterbox; it is not
  copied into `library/` or the repo. Keep recordings outside the repo folder;
  `uploads/` and `voice_refs/` are gitignored as a backstop.
- **No third-party assets are bundled.** All music is synthesized from scratch
  by `engine.py`, all covers are generated by `art.py`, all lyrics are written
  by `lyrics.py` (or an LLM you point it at), and DJ voices come from
  Chatterbox's built-in default voice (or macOS `say` offline) — no songs,
  lyrics, art, or voice samples ship with the repo.

## Claude Code for teammates

The repo ships a shared Claude Code workspace, so any teammate's Claude starts
already wired to the project:

- **Project memory & rules** — `CLAUDE.md` (architecture, commands, the
  no-secrets / no-third-party-assets rules, team workflow).
- **Permissions & guard** — `.claude/settings.json` denies reading `.env`,
  allows direct `main` pushes but blocks force-pushes, and
  `.claude/hooks/guard.sh` blocks destructive commands and commits that
  would leak credentials (runs automatically on every tool call).
- **Slash commands** — `/generate`, `/verify`, `/security-check`
- **Subagent** — `@arranger` (music/synthesis specialist for `engine.py`)

Setup for each teammate:

```bash
npm install -g @anthropic-ai/claude-code   # then: claude  (auth once)

```

Run-from-GitHub option: the repo includes `.github/workflows/claude-code.yml`
(workflow_dispatch). An owner sets the **`ANTHROPIC_API_KEY`** secret
(Settings → Secrets → Actions — server-side, never in the repo), and anyone

### Quick start

```bash
# from this folder
.venv/bin/python generate.py demo          # build the two demo setlists
open player.html                            # or: generate.py serve → http://localhost:8777/player.html
```

The player auto-advances: station ID → DJ intro → song → DJ intro → song …,
spin-visualizer, lyrics, downloads, keyboard shortcuts (space, ←/→, ↑/↓).

## The three parts

| Part | How | Customization |
|---|---|---|
| Songs | `engine.py` — seeded procedural composition (harmonic synthesis, melodic motifs, synthesized drums, FFT reverb, sidechain, vinyl noise) | genre, bpm, key-root, scale (major/minor/dorian/phrygian/lydian/mixolydian/pent_minor), mood 0–1, length, seed, optional robotic vocoder vocals (`--vocals`) |
| Cover art | `art.py` — seeded SVG per style family (synthwave grid, lofi room, geometric, pixel, landscape, aurora, rings, glitch) | hue follows genre, brightness follows mood, layout from seed; `--style` overrides, `--png` rasterizes via qlmanage |
| DJ booth | `dj.py` — scripts (template, or Qwen on 9001 with `--llm`) that bridge from the previous song to the next; speech by Chatterbox on 9008, macOS `say` as offline fallback | personas: `nova` (club), `lana` (chill), `rex` (radio), `vox` (robot), `moon` (whisper); auto-matched to genre. Custom voice: `--voice-ref me.wav`. A clip that fails is dropped so the queue never waits on it |

Genres: `lofi`, `synthwave`, `techno`, `chiptune`, `cinematic`, `ambient`.

## Recipes

```bash
# one song with everything tuned
.venv/bin/python generate.py song --genre synthwave --seed 7 --bpm 104 \
    --key-note 57 --scale dorian --mood 0.8 --length long --vocals --llm

# a themed setlist with DJ commentary
.venv/bin/python generate.py setlist --name "Rainy Study Hour" \
    --theme "rain on glass, warm lamps" --genres lofi,ambient --count 6 \
    --seed 20261023 --llm

# one DJ clip / one cover
.venv/bin/python generate.py dj --title "Neon Rain" --genre synthwave \
    --persona nova --llm --prev-title "Paper Lanterns"
# same, in a cloned voice (recording kept outside the repo)
.venv/bin/python generate.py dj --title "Neon Rain" --llm --voice-ref ~/voice/me.wav
.venv/bin/python generate.py art --genre techno --title "Iron Pulse" \
    --seed 99 --png

# rebuild a setlist from scratch
.venv/bin/python generate.py setlist --name "Synthwave Sunday" --genres synthwave,techno --count 5 --force --llm

.venv/bin/python generate.py list       # what's in the library
.venv/bin/python generate.py serve      # http://localhost:8777/player.html
```

Seeds make every run reproducible: same seed + params ⇒ identical song.

## Library layout

```
library/
  index.js                  setlist picker (regenerated each build)
  synthwave-sunday/
    playlist.js             what player.html loads
    setlist.json            same data, human-readable
    song_01/  song.wav song.mp3 cover.svg lyrics.txt info.json [vox.wav]
    dj_00.wav|mp3           station ID (+ .txt transcript)
    dj_01.wav|mp3 …         intros before each track
```

`player.html?set=synthwave-sunday` jumps straight to a setlist.
