# AI Jukebox — project workspace for Claude Code

You are working in **assignment-3** (team: sohrabotrooshi · junqlee22 ·
KristenMWendling · thefrozenfox12 · burnt-ham). The app generates original
songs, cover art, and AI-spoken DJ commentary, and plays setlists in a
Spotify-referenced web player.

## Layout

- `jukebox/engine.py` — numpy procedural music synthesis (harmonic-synth
  instruments, chord progressions, melodic motifs, synthesized drums, FFT
  reverb, sidechain, vinyl noise). `SR = 44100`, `GENRES` dict drives
  instrument/drum/bass config. `Song.arrange()` builds section structure.
- `jukebox/art.py` — seeded SVG cover art per genre style family.
- `jukebox/lyrics.py` — deterministic title/lyrics/artist writer + word banks.
- `jukebox/dj.py` — DJ personas, script writing (LLM or offline templates),
  macOS `say` TTS.
- `jukebox/generate.py` — CLI: `song`, `setlist`, `dj`, `art`, `demo`,
  `serve`, `list`. Writes `library/<setlist>/...` + `playlist.js`/`index.js`.
- `jukebox/player.html` — single-file player; loads `library/index.js`.
- `library/` — GENERATED OUTPUT, gitignored. Never commit it.
- `jukebox/verify.py` — integrity checker; the gate for any change.

## Commands

- Generate the demo setlists: `python3 jukebox/generate.py demo --force`
- One custom setlist: `python3 jukebox/generate.py setlist --name "X" --genres lofi,techno --count 6 --seed 42`
- Run the integrity gate: `python3 jukebox/verify.py`
- Serve locally: `python3 jukebox/generate.py serve` → http://localhost:8777/player.html
- Python venv with numpy lives at `jukebox/.venv`; use
  `jukebox/.venv/bin/python` for anything importing numpy.

## Conventions

- **Determinism is sacred.** Same seed + params ⇒ identical song, cover, and
  DJ clip. Random calls must go through `np.random.default_rng(seed)` or
  `rng.integers`, never the global numpy/`random` state. Seeded output is part
  of the product (README documents it).
- **Never commit `library/`, `.venv/`, `.env`, or any generated audio.**
- **No user uploads, no voice-reference recordings, no third-party music /
  lyrics / art / voice samples** may ever enter the repo — everything must be
  generated by the app (that is an assignment rule, not a style guide).
- **Credentials stay local:** `jukebox/.env` (gitignored) or env vars feed
  `JUKEBOX_LLM_URL/MODEL/KEY`. Do not print, read, or commit keys. The guard
  hook blocks secret-looking staged changes.
- Target: dry, typed Python; keep numpy code vectorized (no per-sample loops
  over the timeline).
- A new genre = a `GENRES` entry + progression set + lyric banks + art style
  mapping + dj persona matching; keep all five in sync.

## Workflow rules (team)

- Branch + PR + teammate review before merging; never push or force-push to
  `main` (the guard hook enforces this).
- After touching the generator, run `python3 jukebox/verify.py` and the demo
  rebuild before proposing a merge.
